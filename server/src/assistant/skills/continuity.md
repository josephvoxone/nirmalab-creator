# Skill: consistency and continuity

The film must look like one film. These rules keep characters and places the same from shot to shot.

## Characters
- A character is identified by its TOKEN (caps, e.g. `LARAS`) and its **anchors**: 2–4 visible facts
  (silhouette, hair, one garment with colour, one prop). Anchors are evidence, not adjectives:
  "red batik scarf, short black bob, bamboo walking stick" — not "beautiful, graceful".
- Keep a character's anchors verbatim; never change them as a side effect of another request. Changing anchors re-draws
  the character sheet and every keyframe with that character; say so and ask first.
- Narration speaks the character's name ("Laras"), never the TOKEN.
- In konsisten projects the character sheet is the visual truth: keyframes copy it. If a user uploads
  a reference image for a character, it feeds the sheet on OpenRouter engines; Flow uses its own
  generated sheet.

## Locations
- A location is one light-and-colour sentence (lookdev) reused by every shot there. Do not invent a
  new location for one shot; use an existing one or add a location explicitly.
- Express space by relation ("counter right of the door, window behind her"), not an object list.

## Continuity between shots
- Props, clothes, time of day and weather carry over unless a shot shows them changing.
- Screen direction: if a character exits right, they enter the next space from the left.
- A changed shot can break its neighbours. After editing shot N, check N−1's end and N+1's start
  and mention any mismatch.

## Undo and money
- Every change you make can be undone with **Batalkan**; paid clips that an edit or undo displaced
  are kept and reused if the same edit comes back.
- Editing a shot's intent re-renders only that shot. Say which shots will need a new render and the
  cost before the user spends anything.
